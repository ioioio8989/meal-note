# MEAL NOTE v21

2026-09-22 실사용 피드백이 이전 제품 문서와 충돌하는 경우 이 문서가 우선합니다.

## 제품 흐름

- 홈: 오늘 먹은/먹을 식사, 기관 메뉴, 오늘의 준비, 빠른 기록.
- 메뉴 고르기: 보유 재료 중 오늘 쓸 재료 선택 → 두 가지 익숙한 조합 → 다른 메뉴 보기 → 저녁 선택.
- 우리집 재료: 검색어를 그대로 추가. 보유 목록에서 메뉴 선택으로 연결. 기관 식단은 여기와 설정에서 가끔 등록.
- 기록: 여러 끼니를 한 문장으로 입력 → 날짜·끼니·음식 확인/수정 → 한 번에 저장. 기존 끼니 수정도 유지.
- 아침, 내일, 이후 3일 계획과 간편 식사, 레시피는 메뉴 화면의 접힌 상세에서 접근.

## 추천

음식은 수록된 일반 메뉴 목록만 사용하며 이름을 합성하지 않습니다. 선택 재료를 실제 주요 재료에 포함하는 후보만 우선합니다. 전부 포함할 수 없으면 최대한 포함한 후보와 미반영 재료를 명시합니다. 재추천도 동일한 조건을 유지합니다. 보유 재료·추가 구매·최근 식사·당일 실제 기록·기관 메뉴가 순위에 반영됩니다. 국 중복, 전복 주메뉴의 불필요한 중복을 피합니다. 선택/직접 수정한 기존 계획과 실제 기록은 자동 추천이 덮어쓰지 않습니다.

## 영양 흐름

실제 기록과 기관 예정·미래 계획을 구분합니다. 막대는 음식명 및 일반 주재료에서 추정한 식품 출처의 등장일이며 영양소 섭취량·충족률이 아닙니다. 돼지국밥의 돼지고기와 밥, 토마토리조또의 토마토와 쌀은 반영하지만 리조또의 치즈·고기·기름은 임의로 추가하지 않습니다. 모르는 음식은 확인되지 않았다고 표시합니다.

## 데이터와 서비스 경계

mealnote.state.v2 키와 schemaVersion 3을 유지합니다. 기존 v2 → v3 이관, 하루 전체 원문, 음식 ID, 실제 기록, 백업/복원 및 동시 편집 충돌 보호를 유지합니다. 로그인·원격 DB·외부 AI·음성 전송·유료 서비스를 도입하지 않습니다.

기관 식단은 여러 날짜 텍스트를 기기 내에서 구조화하고 수정·확인 후 저장합니다. 사진은 참고 미리보기이며 OCR 기능이 아닙니다. 음성은 브라우저가 한국어 기기 내 인식을 지원하고 준비된 경우에만 시작하며 원격 인식으로 전환하지 않습니다. 외부 서버가 필요한 push는 미구현입니다.

## 향후 변경 원칙

실사용 입력 감소를 우선합니다. 음식별 수정의 형제 항목과 의존 재료·장보기·준비를 함께 검증합니다. 데이터 손실 가능성이 큰 변경, 외부 개인정보 전송, 유료 서비스·계정 도입은 사용자 결정 후 진행합니다. 모바일 브라우저 A–H 시나리오와 tests/test-model.cjs를 확인합니다.
